# 学生数据管理系统 · 保险业务模块重构设计提案

> 目标：基于现有核心业务逻辑重新规划保险模块。**初始化导入功能保留并加固**；其余模块重新设计，本文为待讨论的设计方案，未进入实现。

## 0. 现状问题回顾（一句话）
功能闭环完整，但"重单条、轻批量"；核心状态 `supervisor_flag` 是一堆散落的硬编码中文，且年级/班级筛选、批量接口已具备能力却未接前端，导入依赖外部 CDN。

## 0.5 实际业务流程（用户澄清，已对齐）
学生**在校共 3 年，按学年顺序办理 3 次保险**，由系统数据驱动：

- **第 1 年 · 学平险（首批）**：新学生 `supervisor_flag` 默认空。由**初始化导入**批量创建——admin 在系统外办完对应学年的保险后，导入填"主管标记"+"保单号"+"到期时间"。**导入按该生 `grade` 计算当前批次**：普通 2026 新生创建"第 1 年学平险"，转学生（grade=2025级）自动创建"第 2 年学平险"。不走登记/审批。
- **第 2 年 · 学平险**：能否进待办取决于**保险业务员是否已登记该生缴费**；有缴费（且新缴费日期在第 1 年到期日之后）才办理第 2 次学平险。
- **第 3 年 · 实习就业险**：取决于**实习险缴费日期是否已填**；已缴则办理。实习就业险在系统中**无保单号**，仅记缴费日期。

**关键结论（澄清后修正此前误判）**
- 学平险只存"当前生效保单号"，过期作废、次年覆盖——**单组字段模型正确，无需历史表**。
- 实习就业险系统无保单号字段，**符合业务**（仅记缴费日期）。
- 待办是**缴费驱动**：未登记缴费的学生不出现。
- 导入是 **upsert**：既建新生第 1 年记录，也覆盖/更新老生的缴费与已有保险记录。

**第 2/3 年保险类型的判定（改进的实现方法）**
不再靠人眼比对"缴费日期是否贴近到期日"，改为以 **`grade`（学籍年级/级）为唯一基准**——该字段在你的新生入学算法中已被预调（转学生 `grade = 入学年 − 1`，普通生 `grade = 入学年`），因此可直接作为"学生在读第几年"的权威基准，**无需再判转学、无需特殊分支**。

1. **学年/批次引擎公式**
   `current_batch = current_school_year − grade + 1`
   （`grade` 取值如 `2025级`、`2026级`，即学籍起始年份；`enrollment_year` 只是入学算法的输入，保险批次逻辑统一用 `grade`）
   - 普通 2026 新生：`grade=2026级` → `2026 − 2026 + 1 = 1` → 第 1 年学平险。
   - **转学生**（入学算法已使其 `grade=2025级`，即便 `enrollment_year=2026`）：导入进系统的 `current_school_year=2026` → `2026 − 2025 + 1 = 2` → **第 2 年学平险**（自动落位）。
   - `grade=2024级` 生，`current=2026` → `2026 − 2024 + 1 = 3` → 第 3 年实习就业险。
   - 公式对普通生/转学生**统一适用**，因为 `grade` 已含转学折算。
   - `current_school_year` 为学校学年基准（默认取当前自然年；若贵校学年从 9 月起算需确认口径）。`current_batch > 3` 视为保险已全部办完。
2. **交叉校验（辅助，非主逻辑）**：提取当前学平险到期时间——若已过期且记录了新的学平险缴费，则确认进入下一批次；该逻辑在待办触发时作为提示，并以第 1 步的 `grade` 公式为准。
3. 第 2 年候选：`current_batch=2` 且存在第 1 年到期日且新学平险缴费日期在其之后 → 系统预填"第 2 次学平险"；
4. 第 3 年候选：`current_batch=3` 且实习险缴费日期已填 → 系统预填"实习就业险"；
5. **主管在审批/办理页只做"确认"或改选"不参保"**，系统不替人做最终决定。
（学生表已有 `enrollment_year`、`admission_type`、`grade` 字段，无需新增 schema。保险批次以 `grade` 为唯一基准。）

## 1. 设计原则
1. **角色驱动**：财务(登记) / 财务主管(审批) / 保险员(待办结案) / 全员(查询) / admin(导入)
2. **状态机显式化、单一事实来源**：消除"拼错字就从待办/审批消失"的隐性 bug
3. **批量优先**：所有列表支持多选 + 批量操作
4. **大列表可用**：筛选 + 分页，不再一次性渲染整棵 DOM
5. **导入能力保留并加固**

## 2. 统一保险状态机（本次重建的地基）
当前 `supervisor_flag` 实际只有 6 个语义状态（含空），散落在 `blueprints/insurance.py`、4 个前端 JS、`config.py` 三处；且 `config.py:172` 的 `INSURANCE_SUPERVISOR_FLAGS` **漏了"实习就业险"**（已是 bug）。

重建为单一枚举 + 展示文案（存储值兼容历史数据，不改变落库字符串）：

| 状态码 | 存储值(stored) | 展示文案 | 进入动作 |
|---|---|---|---|
| `UNREGISTERED` | NULL / '' | 未登记 | 初始 |
| `PENDING_XUEPING` | 按计划办理学平险 | 学平险待办结 | 审批通过(学平险) |
| `PENDING_INTERN` | 按计划办理实习就业险 | 实习险待办结 | 审批通过(实习险) |
| `EXEMPT` | 不参保 | 不参保 | 审批否决 |
| `DONE_XUEPING` | {YYYY}年度学平险办结（如 2026年度学平险办结） | 学平险已办结 | 保险员结案 |
| `DONE_INTERN` | {YYYY}年度实习就业险办结（如 2025年度实习就业险办结） | 实习险已办结 | 保险员结案 |

注：待办结态（PENDING_*）跨年**复用同一存储值**（第 1、2 年待办结都写"按计划办理学平险"）；**办结态才带年份前缀**，格式为 `{YYYY}年度`（4 位年，如 `2026年度学平险办结`、`2025年度实习就业险办结`），由 `grade` 推算（`current_batch`）或取导入提供值。实习就业险无独立保单号字段，仅记缴费日期。

> ⚠️ **已知实现不一致（待修）**：现有待办办结代码写 `2026学平险办结`（4 位年、无"年度"），与上面真实格式 `26年度学平险办结` 不一致，会导致按 flag 查询/统计错位。Phase 1/8 需统一为 `{YYYY}年度` 格式（前后端都改，含 `todo.html` 的 `year+'学平险办结'` 与后端 complete 逻辑；`year` 取 4 位年）。

**年份前缀的任意年份兼容（回应"2027 年能否正确存前缀"）**：办结态前缀必须由**年份感知的格式化函数**生成，绝不硬编码某一年。采用 **4 位年 `YYYY年度`**（用户决策：导入统一为 YYYY，消除世纪歧义）。骨架：
- `yyyy(y) = String(y)`；`DONE_XUEPING(y) = `${yyyy(y)}年度学平险办结``；`DONE_INTERN(y) = `${yyyy(y)}年度实习就业险办结``。
- 反向解析：`parse_flag_year(flag) = /(\d{4})年度/.exec(flag) ? parseInt(m[1]) : null`。
- 如此 2027 → `2027年度学平险办结`、2099 → `2099年度…` 均正确，且无 2 位年的世纪翻转歧义。
- **前缀来源**：导入时取自用户提供的 主管标记（轻量归一化后原样存）；**系统内办结时取自该批次的学年**（`grade + batch − 1`，或 `current_school_year`），而非点击当天的 `new Date().getFullYear()`——避免 clerk 在 2027 年办结一笔 2026 批次却被误标成 `2027年度`。

**落地方式**
- `config.py` 定义 `InsuranceStatus` 枚举/常量字典，所有读写引用它；`INSURANCE_SUPERVISOR_FLAGS` 改为由枚举派生（顺手修 bug）。
- 前端 `static/js/insurance_status.js` 镜像同一份常量，所有页面共用。
- 不再允许自由字符串写入 `supervisor_flag`。

## 3. 模块 / 页面重组（已决策：保留三个独立页 + 共享组件层）
保留现有「登记 / 审批 / 待办」三个独立路由页面，抽出一个共用的**状态常量 + 批量操作组件**供三页复用；「保险查询」「初始化导入」独立保留。

| 页面 | 角色 | 能力 |
|---|---|---|
| 登记页 (insurance/register) | 财务/保险业务员 | 缴费登记（填学平/实习缴费日期等）+ 树形行内编辑 + **多选批量登记**；学生缴费登记后才进入办理待办 |
| 审批/办理页 (insurance/approve) | 财务主管 | 按到期分组；**系统按学年+缴费预填类型**，主管单条/批量确认或改选"不参保" |
| 待办页 (insurance/todo) | 保险员 | 按学校×类型 + **批量结案** + 导出 |
| 保险查询 | 全员 | 搜索/脱敏/徽章/空状态（样板保留） |
| 初始化导入 | admin | Excel 上传→预览→后台线程导入（**保留 + 加固**） |
| 共享层 | — | `InsuranceStatus` 常量 + 批量勾选/操作 JS 组件，三页复用 |

## 3.1 审批页「批次上下文」（财务管理员视角，用户 16:03 需求）
审批阶段，财务管理员需一眼看清"该生处在第几年、历史批次记录是什么、下一步办什么"，避免来回切页核对。具体要求：
- 对"最近一批保险要到期"的学生，直观看到其 **保单到期时间**；
- 看清其是否已有 **第 1 年学平险 参保记录**；
- 若已有 **第 2 年学平险 记录**，能明确看见 **实习就业险缴费日期**。

**现状对照**：当前审批页已按"到期时间"分组（分组头即保单到期时间），行/弹窗也已含 学平险缴费日期、实习险缴费日期。**缺口**：现有 学平险 记录未标注"第几年"，管理员无法在列表中一眼区分"这是第 1 年记录（将办第 2 年）"还是"第 2 年记录（将办实习险）"。

**改进设计（审批页新增「批次上下文」）**
- 每个学生行/弹窗增加 **批次标签**：现有 学平险 记录标注为"第 N 年学平险 参保记录"，`N = pending_batch − 1`。
- **待办批次 `pending_batch` 的判定**（决定 N 与"下一步动作"）：
  - 队列由"新缴费"触发进入 → 新 学平险 缴费 → `pending=2`（现有记录即第 1 年）；实习险缴费已填 → `pending=3`（现有记录即第 2 年，并醒目展示实习就业险缴费日期）。
  - 与 grade 引擎交叉校验：`pending_batch` 应 ≈ `current_school_year − grade + 1`；不一致时标黄提示。
- **保单到期时间**：分组头保留，并加"即将到期 / 已过期"徽标，便于优先处理临期单。
- **实习就业险缴费日期**：当 `pending=3` 时在上下文区醒目展示，并注明"因已有第 2 年学平险记录"。

**已决策（用户 16:03 需求拍板）**
- **批次标注规则**：现有 学平险 记录标为"第 2 年"当且仅当 `internship_insurance_pay_date` 已填（即该生已走到实习阶段），否则标为"第 1 年"。该规则直接对应"已有第 2 年学平险记录时明确看实习缴费日期"的原话。
- **grade 引擎交叉校验**：`pending_batch` 应 ≈ `current_school_year − grade + 1`；两者不一致时批次标签旁标黄提示（数据异常预警），但不阻断操作。
- **不加历史表**：审批通过后第 1/2 年记录被下一年覆盖，本需求仅限审批阶段看上下文，单组字段已满足；"已审批/查询"页无需回溯历史批次。

## 3.2 登记页交互（缴费登记 + 批量 + 批次提示 + 筛选接线）
角色：财务/保险业务员。核心动作 = 记录缴费日期，触发后续待办（缴费驱动）。
- **批次提示（防错）**：每行按 grade 引擎显示"当前应为第 N 年"徽标（N=current_batch）。业务员录入学平险缴费 vs 实习险缴费时有上下文对照，避免给第 3 年学生误录学平险。
- **行内编辑（保留）**：学平险缴费日期 / 保费 / 实习险缴费日期 单元格点击编辑（现有能力不动）。
- **批量登记（接 `register-batch`，新增）**：行首加勾选框 + 顶部"批量设置"工具条，选字段（缴费日期/保费/实习险日期/保单号）+ 统一值，一键应用到所选多行。后端该接口已存在未接。
- **筛选接线（复活死代码）**：`insurance_register` 路由已算好 年级/班级/专业 filter 却没传 UI → 暴露 filter 控件，对树做客户端过滤。
- 边界：登记页只写"缴费记录"，不写 `supervisor_flag`（状态由审批/办结流转）。

## 3.3 待办页交互（办结区分学平/实习 + 逐人保单号 + 导出尊重筛选）
角色：保险员。待办 = `supervisor_flag` 已审批（按计划办理学平险/实习就业险）且未办结。
- **办结弹窗按类型自适应**：
  - 学平险：提供"统一设置"（一个保单号+到期套用全批，现有）与"逐人设置"（列出本批学生，每人可填各自保单号+到期，预填其现有学平险记录）两种模式——实习/学平常每人一单。
  - 实习就业险：系统无保单号字段 → 隐藏保单号输入，仅确认办结（写 `{year}实习就业险办结`），并注明"实习就业险无保单号"。
- **导出尊重筛选（修复误导）**：当前导出忽略搜索框、默认全校。改为把当前搜索词传入导出（`/api/insurance/todo/export?search=`），导出与界面所见一致。
- **批次上下文（可选）**：每行显示"第 N 年"徽标，与审批页一致，便于保险员理解本批在办什么。

- **办理批量**：接 `api_insurance/approve`（已存在未接）→ 多选 + 批量确认系统预填的类型 / 改选"不参保"。
- **待办结案**：现有"学校×类型"批量保留，新增"逐人保单号"模式（实习/学平常每人一单）。

## 5. 筛选接线（保留树形，接已有 filter）
- **保留树形展开**呈现（用户决策）；不引入扁平分页列表。
- 年级/班级/专业筛选**真正接线**：当前 `insurance_register` 已算好 filter 却没传给 UI，是死代码——把 filter 暴露给前端，对树做客户端过滤。
- 性能：典型学校规模下树形可接受；如后续确有超大批量，再单独评估分页（不在本次范围）。

## 6. 初始化导入（保留 + 加固）
**保留链路**：Excel 上传 → 预览 → 后台线程导入（进度轮询），**本次仅加固，不改主流程**。
**语义为 upsert**：按 **身份证号** 匹配学生，建/更新该生**当前批次**（由 `grade` 计算）的保险记录——普通 2026 新生为"第 1 年学平险"、转学生（grade=2025级）自动落位"第 2 年学平险"；老生覆盖/更新缴费与已有保险记录。

**加固项**
- **去 CDN（可靠性）**：前端用 jsdelivr 的 xlsx 库解析，离线即挂 → 改为**后端解析**（复用项目已有的 openpyxl），前端只上传文件（FormData）、展示后端回传的预览与进度。模板 6 列不变：身份证号 / 学平险保单号 / 学平险缴费日期 / 学平险到期时间 / 实习险缴费日期 / 主管标记。
- **主管标记：直接接受真实格式 + 轻量归一化（基于实际样本修正）**：你提供的样本显示，主管标记是**结构化**的——`2026年度学平险办结`、`2025年度学平险办结`、`2025年度实习就业险办结`（即 `{YYYY}年度{类型}办结`，YYYY=4 位年），与 §2 办结态枚举**完全一致**，无需清洗 Excel。处理：
  1. **直接接受** `YYYY年度学平险办结` / `YYYY年度实习就业险办结` / `按计划办理学平险` / `按计划办理实习就业险` / `不参保`；同时**容忍 2 位年写法**（`26年度…`）并归一化为 4 位（`2026年度…`）；
  2. **轻量归一化**仅处理格式变体：2 位年→4 位（`26年度`→`2026年度`）、`年`→`年度`、词序微调；明显同义（`不参保/未参保/放弃`→`不参保`）；
  3. **留空 → 默认** `按计划办理学平险`（流入待办由保险员办结），不阻断；
  4. 结果汇总标注"已归一化 N 条（含未识别 M 条）"。
  - 落库值始终是规范枚举（与 Phase 1 一致，4 位年）。样本中的"办结"值说明**导入创建的是已完成保险**（系统外已办完），学生导入后即记为办结、不再进待办——除非主管标记本身是待办结态。
  - 反例警示：此前担心的"已办/参保"等自由文本在实际样本里并不存在，归一化保持轻量即可。
- **批次感知写入**：匹配到学生后算 `current_batch`；`batch=3`（grade 2024级）时**忽略学平险列**（该生应为实习就业险，系统无学平险/保单号字段），仅写实习险缴费日期 + 实习类主管标记；学平险列有值则提示"该生应为实习就业险，学平险列已忽略"。
- **匹配缺失处理**：身份证号未匹配到任何学生 → 计入"跳过/失败"并在结果汇总列出（保险导入只更新现有学生，不负责新建学生档案；如需导入即建档案另议）。
- **全量覆盖语义（用户明确：导入为全量数据）**：匹配到的学生，**该行提供的保险列整体覆盖**其库内对应字段——含把旧的 2 位年 `26年度…` 覆盖为 4 位年 `2026年度…`。**一次全量导入即完成 2 位→4 位迁移，无需单独迁移脚本**。空单元格按"覆盖"语义清空该字段（Excel 为该生该列的完整真相）；若担心误清空，可切"仅更新有值列"增量模式。未匹配的学生记录不动（更安全，不误删）。
- **结果状态汇总**：导入结果页增加**批次分布**（多少条成为第 1/2/3 年）、各状态计数、失败明细，替代当前仅进度数字。

**导入后流转**：导入按模板"主管标记"写入状态——若为**办结态**（如 `26年度学平险办结`，即样本中的真实情况，系统外已办完），学生直接记为**已办结**，不进待办；若为**待办结态**（`按计划办理学平险` 等），才流入待办由保险员办结。第 2/3 年走系统内 登记缴费 → 审批 → 办结。
